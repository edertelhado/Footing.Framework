Camadas, fluxo e princípios.

== Camadas

[source,mermaid]
----
flowchart LR
  Controller --> Service
  Service --> Repository
  Repository --> Dapper
  Dapper --> Factory["IDbConnectionFactory"]
  Factory --> DB[("PostgreSQL / Firebird")]
  Service --> EB["EventBus Channel"]
  EB --> Handler["IEventHandler Priority"]
  Service --> Batch["SqlBatch chunked"]
  MigrationRunner --> Factory
  OTel["ActivitySource"] -.-> EB & Dapper & Batch
  Health["Health Checks"] -.-> Factory & EB
----

== Fluxo DI Walk → Lifecycle → Bus

[source,mermaid]
----
flowchart TD
  Scan["Assembly.GetTypes"] --> Filter["Where Has Injectable Service Repository"]
  Filter --> Lifetime["Map Attribute to Lifetime"]
  Lifetime --> Register["Add ServiceDescriptor"]
  Register --> Listeners["RegisterEventListeners"]
  Register --> Lifecycle["PostConstruct PreDestroy"]
----

*Princípios:* agnóstico a banco, SPI `IOutboxStore/IIdempotencyStore/IMigrationJournal`, `<3.5K LOC`, fail-fast de estrutura vs fail-safe de dados.

== Auto-configuration (TryAdd)

`AddMigrations`, `AddEventBus`, `AddFootingHealthChecks` registram defaults via `TryAddSingleton`. Se o app registrar `AddSingleton<IMigrationJournal, MeuJournal>` antes ou depois, o custom vence.
