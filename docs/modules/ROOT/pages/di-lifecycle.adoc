== Atributos

[cols="1,1,2"]
|===
| Atributo | Lifetime padrão | Uso

| `[Injectable(Lifetime)]`
| obrigatório informar
| Qualquer classe que precise de DI

| `[Service]`
| Transient
| Serviços sem estado

| `[Repository]`
| Scoped
| Acesso a dados
|===

[source,csharp]
----
[Service]
public class UserService(IUserRepository repo) { }

[Repository]
public class UserRepository(IDbConnectionFactory f) { }

[Injectable(InjectableLifetime.Singleton)]
public class CacheManager { }

[Injectable(InjectableLifetime.Scoped)]
public class TenantScope { }
----

== ResolverExtensions

*   Cria via `ActivatorUtilities.CreateInstance` (resolve deps DI)
*   Injeta `[InjectConfig]` de `IConfiguration`
*   Executa `[PostConstruct]` (sync/async)
*   Registra `[EventListener]` no EventBus
*   `DiSmokeTests` 2 testes agnósticos `GetServices<IRepo>.Count==1 + ValidateScopes`

== Lifecycle — PostConstruct / PreDestroy

[source,csharp]
----
public class EmailService {
  private SmtpClient? _client;

  [PostConstruct]
  public void Initialize() => _client = new SmtpClient("smtp.example.com");

  [PostConstruct]
  public async Task InitializeAsync() => _client = await CreateClientAsync();

  [PreDestroy]
  public void Cleanup() => _client?.Dispose();
}
----

Suporta `void`, `Task`, `ValueTask` — múltiplos `[PostConstruct]` invalido (`InvalidOperationException`).

== Como funciona

O scan utiliza reflexão sobre assemblies explícitos, mapeando atributos `[Injectable]`, `[Service]` e `[Repository]` para `ServiceDescriptor`. Determinístico e auditável — sem source generators ou mágica.

== Config — InjectConfig

[source,csharp]
----
public class EmailSettings {
  [InjectConfig("Smtp:Host")]
  public string? Host { get; set; }

  [InjectConfig("Smtp:Port")]
  public int Port { get; set; }
}
// preenchido via IConfiguration automaticamente pelo ResolverExtensions
----

TIP: Para testes, use `ResolverExtensions` direto sem Host — ver `DiSmokeTests.cs`.
