== Arquitetura

[source,mermaid]
----
flowchart LR
  Controller --> Service["Service [Service]"]
  Service --> Repo["Repo [Repository]"]
  Repo --> Dapper
  Dapper --> Factory["IDbConnectionFactory"]
  Factory --> DB[("PG / Firebird / dbf\n(via SPI)")]
  Service --> EB["EventBus\nChannel bounded 100\nFullMode.Wait"]
  EB --> Handler["IEventHandler<T>\n[EventListener] Priority"]
  Service --> Outbox["OutboxProcessor\npoll 2s Batch 100"]
  Outbox --> Store["IOutboxStore\nNpgsql/Firebird/dbf"]
  Service --> Batch["SqlBatch\nVALUES chunked 500/2100"]
  Migrations["MigrationRunner\nY/N CHAR(1)"] --> Factory
  OTel["ActivitySource\nFooting.Framework"] -.-> EB & Dapper & Batch
  Health["/health\nDbHealthCheck + EventBusHealthCheck"] -.-> Factory & EB
----

*Princípios:* agnóstico DB (GLOBAL_RULES 59L), SPI `IOutboxStore/IIdempotencyStore` 0 deps, `<3.5K LOC`, `11 GeneratedRegex` source-gen AOT, fail-fast estrutura vs fail-safe dados.

== Versionamento Antora

`antora.yml` `version: 3.4` travado por tag `v3.4.2` — este portal é snapshot `3.4.2`. `v3.5.0` revisado 0.7 SP `UseTransaction Won't definitivo` (DDL transacional agnóstico não suportado, mesmo com BUY — `MSSQL` tolera mas não recomenda, `Firebird/dbf/SQLite` não permitem DDL em transação; `AutoTransaction=false` agnóstico, `BEGIN/COMMIT` no `.sql` se `PG`; `throw NotSupportedException` descritivo — ver xref:migrations.adoc[migrations] e `GLOBAL_RULES §1`).
